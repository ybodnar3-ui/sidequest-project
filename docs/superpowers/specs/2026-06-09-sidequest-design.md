# SideQuest — Design Document

**Date:** 2026-06-09
**Status:** Approved (MVP scope)
**Author:** Yura + Claude

---

## 1. Vision

**SideQuest** — персональний «майстер гри життя». Щоранку користувач отримує **один**
персональний сайд-квест (5–15 хв), адаптований під місто, погоду й настрій. Виконав →
відмітив → отримав нагороду → стрік росте. Мінімум тиску, максимум відчуття «я сьогодні
зробив щось нове й цікаве».

Продукт будується **спершу під одного користувача (власника)**, але з архітектурним
заділом на багатокористувацьку SaaS-версію з підписками.

### Goal
Працюючий продукт, який щодня надсилає круті, різноманітні, неважкі (5–15 хв) сайд-квести,
що урізноманітнюють життя. Опційно — продаж за підписку ($2–5/міс).

### Non-Goals (поки що)
- Реальні платежі / Stripe (Фаза 3).
- Багатокористувацькість і онбординг чужих юзерів (Фаза 3).
- Жорстка верифікація доказів (опційний доказ зараз, посилення пізніше).
- Геоквести, що вимагають далеких поїздок (свідомо тримаємо квести легкими, ~5–15 хв).

## 2. Architecture

| Шар | Технологія | Чому |
|-----|-----------|------|
| Фронтенд | **Next.js (App Router)** як **PWA** | Один код, ставиться на iOS/Android через «На головний екран», офлайн-оболонка, веб-пуші. Найшвидший старт, $0, без Apple-акаунта. |
| Бекенд | **Next.js API routes / server actions** на **Vercel** | Безкоштовно, серверна логіка поруч із фронтом. |
| БД + Auth + Storage | **Supabase** (Postgres + Auth + Storage) | Безкоштовний тариф, швидкий старт, готовий до мультиюзера, сховище для фото-доказів. |
| AI | **Anthropic Claude API** (server-side) | Генерує персональний квест із контексту. Модель: `claude-haiku-4-5` для дешевизни/швидкості генерації, з можливістю апгрейду на Sonnet за потреби якості. |
| Погода | **Open-Meteo** | Безкоштовно, без API-ключа. |
| Геолокація | Browser Geolocation API + ручне перемикання міста | Користувач часто змінює країни. |
| Нагадування | **Web Push (VAPID)** + **Vercel Cron** | Щоранку cron генерує квест і шле пуш у налаштований час. |

**Принцип:** уся бізнес-логіка (AI-генерація, нагороди, прогрес) живе на бекенді й
переноситься 1-в-1, якщо в майбутньому фронт переписується на нативний (Expo/Capacitor).

## 3. Core Daily Loop

1. Зранку (cron у налаштований час) генерується квест дня → надсилається пуш:
   *«Доброго ранку! Як настрій сьогодні?»*
2. Користувач тапає пуш → обирає настрій (емодзі-шкала) → **відкривається квест дня**
   (маленький ритуал-інтрига).
3. Картка квесту показує: назва, опис, категорія, орієнтовні хвилини, нагорода в XP.
4. Користувач виконує → тисне «Готово» → **опційно** прикріплює фото/текст-доказ.
5. **Святкування:** +XP, стрік +1, прогрес рівня, анімація.
6. Квест падає в **журнал** виконаних (стрічка досягнень).

> Примітка щодо настрою: чек-ін настрою — частина ранкового ритуалу. Якщо квест уже
> згенеровано до чек-іну (cron), настрій застосовується як уточнення/переген, або
> впливає на генерацію наступного дня. Деталь уточнюється в плані.

---

## 4. Quest Rhythm (configurable, default = 1/day)

Налаштування режиму доставки:
- **Тільки ранковий** (дефолт) — 1 квест зранку.
- **Тільки рандом-попап** — квест «вискакує» у випадковий час дня.
- **Ранковий + попапи** — ранковий набір + 1–2 несподівані попапи.

Плюс налаштування кількості. **Стартуємо з 1 квест/день** — це навмисний дизайн: ненапряжно.

---

## 5. Categories

Чотири категорії, кожна вмикається/вимикається в налаштуваннях:
- **Соціальні / люди** (фаворит власника — більша вага за замовчуванням)
- **Тіло / рух / здоров'я**
- **Творчість / навчання**
- **Пригоди / місто**

AI підбирає квест у межах увімкнених категорій і чергує їх (на основі історії), щоб
уникати одноманітності.

---

## 6. Reward System (4 modes, selectable)

Базовий двигун — **XP + рівні + стріки** — завжди ввімкнений. Поверх нього користувач
вмикає модулі (модульна архітектура, без дублювання логіки):

| Режим | Опис | MVP-реалізація |
|-------|------|----------------|
| **XP + рівні + стріки** | Базова віртуальна гейміфікація | Завжди ввімкнено |
| **🎁 Магазин реальних нагород** | Користувач сам задає винагороди й ціну в XP, «купує» за зароблене | Таблиця custom_rewards + redemptions |
| **💰 Грошовий банк / застава** | Облік грошової ставки на виконання | **Ручний журнал** (без реальних платежів у MVP) |
| **🔀 Комбо** | Кілька модулів одночасно | Просто вмикаються кілька прапорців |

«4 варіанти на вибір» = базовий XP-двигун + два опційні модулі, які можна комбінувати.

---

## 7. Proof of Completion

**Опційний** доказ: фото або текст, прикріплений при виконанні. Зберігається в Supabase
Storage. Логіку легко посилити пізніше (обов'язковий доказ, бонус-XP за доказ, тощо).

---

## 8. Data Model (high-level)

- **profiles** — налаштування користувача: режим ритму, увімкнені категорії, увімкнені
  модулі нагород, часовий пояс, поточна локація, час ранкового пушу.
- **quests** — згенеровані квести: дата, назва, опис, категорія, est_minutes, статус,
  proof_url / proof_text, completed_at, xp_value.
- **xp_ledger** — транзакції XP (нараховано/витрачено), для обчислення рівня та балансу.
- **streaks** — поточний і найкращий стрік, дата останнього виконання.
- **custom_rewards** + **redemptions** — товари магазину нагород і викупи.
- **money_stakes** — записи ручного грошового журналу.
- **mood_checkins** — дата + настрій (для персоналізації).

> Точні схеми (поля, типи, RLS-політики) визначаються в імплементаційному плані.

---

## 9. AI Quest Generation

Серверний виклик Claude API формує квест із контексту:
- Локація (місто/країна) + погода (Open-Meteo).
- Настрій (останній чек-ін).
- Увімкнені категорії (з вагами; соціальні — вищий пріоритет).
- Історія останніх N квестів (щоб не повторювати й чергувати категорії).
- Обмеження часу: 5–15 хв.

Вивід — структурований (назва, опис, категорія, est_minutes, suggested xp) для запису в `quests`.

---

## 10. Phasing

- **Фаза 1 (MVP під власника):** весь щоденний цикл — AI-квест з контекстом, виконання +
  опц. доказ, XP/стрік, журнал, PWA-встановлення + веб-пуш, налаштування (ритм, категорії).
- **Фаза 2:** модулі нагород (магазин, грошовий банк), повноцінний ритуал настрою, полірування UI.
- **Фаза 3:** багатокористувацькість, онбординг, підписки (Stripe) → продаж.

Кожна фаза — окремий цикл spec → plan → implementation.
